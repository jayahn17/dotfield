# BENCHMARK — what Dotfield measures about itself, and what it only claims

Two parts. **Measured on Dotfield** is written by `node scripts/benchmark.mjs --write` and compared byte for byte by `--check` (`npm run check` runs it with `--quick`; the shipped workflow `.github/workflows/dotfield.yml` runs `npm run check` after `npm test`, but only once dotfield is a repository root: inside son that file is inert, because GitHub reads workflows at a repository root only and son's own workflows never call it). **Competitor feature checklist** is a hand-entered table of `present | absent | unknown` cells copied from [`benchmark-checklist.json`](benchmark-checklist.json), each with a source; its header sentence is regenerated by the script, never typed. There is no numeric score anywhere in this file for anything the script did not run: a competitor is never executed here, so a competitor never gets a number.

The product under test is the whole sentence "a personal professional data center that turns typed JSON into interactive 2D/3D/VR/4D scenes, with an agent loop and sharing". No other system targets that sentence, so the checklist says where a comparison is unfair: diagram tools are checked for privacy they never promised, and knowledge tools for layout they never claimed. The useful reading is per feature, not per column.

## 1. Method

- **Corpus** (`lib/bench/corpus.mjs`): the 8 example scenes (the 7 stamped `examples/scene-<name>.json` and `scene-meet.example.json`) and the 9 non-draft pack scenes with their file digests; the archify fixtures under `test/fixtures/importers/` (accepted or refused with the `DF_IMPORT_*` code) and the 15 archify examples vendored under `test/fixtures/archify/` at the commit its `manifest.json` pins, each imported and measured at `--quality showcase --view 2d`; synthetic tree, two-level clustered and random sparse graphs drawn from `lib/layout/rng.mjs` under fixed seeds, 8–24 character labels, dates spread over one year; one 12-node workflow on `grid` and one on `layered` (prints `not_implemented` until `MODES_2D` has it).
- **Per scene × quality × views** (`lib/bench/measure.mjs`): the real pipeline in process — schema, topology, privacy, layout once, the layout gate, the renderer, the render gate — with status, exit code and failing codes (counts, `blocking`, and `capped` parsed from the layout gate's 200-row sentinel by one regex pinned in `test/benchmark.test.js`), plus the layout metrics of `lib/bench/metrics.mjs`: overlap pairs, label collisions among everything drawn beside the glyphs (measured labels, sublabels, evidence pins, edge labels, order badges, region labels — the layout gate's own pairs, in the scene's theme) with the measured and total label counts, route-through-node, polyline crossings over `edgePolyline()` (today `routePoints()`), stress, neighbourhood preservation at k = 3, edge-length uniformity, containment violations, one-edit stability (one leaf added to the max-degree node, warm relayout with `ctx.incremental`, mean and max displacement of the existing nodes) and the viewBox area ratio against the box each scene committed on 2026-10-07.
- **Probes** (`lib/bench/probes.mjs`): standalone-ness (external references by origin for a default `--view all` render and an `--embed-three` render, importmap mode, SRI), 2D/3D/VR parity (the inverse lift of every 3D position against the 2D table, `positionsVr == toVr(positions3d)`), determinism (`verifyDeterminism()` over every table the layout exposes, for the shipped scenes and through the memo runner for every synthetic and workflow row as well, two renders under one clock), the 4D probes as `true | false | not_implemented` (edge-label truth among them: every drawn edge label's `textLength` equals the `edgeLabelBox()` width the gate measured), the agent surface (SKILL.md, forbidden commands tested, Claude Code hook reminder, MCP tools and annotations, the owner gate), verification (rule codes, repair sentences, receipt fields, a verify round trip) and maintainability (dependencies, files at or over 400 lines, test files; the `test()` count comes from the node:test runner summary in the full bench, never from a grep).
- **`--quick`** (the `npm run check` gate, target under 60 s per Node version): shipped scenes at `checked` and `showcase` with `--view 2d`; the tree family at n = 100 and 500 at `checked`, one in-process run; the archify fixtures and corpus; the quick path in process, in a temp root (`first_output` in the JSON: the architecture template with no out path at `--view 2d` and `all`, then every template at `--quality showcase --view all`); the determinism probe once per scene through a `deps.runner` memo; no fresh-clone spawn, no CLI wall timing, no 3D render, no timing at all — so the quick JSON is byte-reproducible under one `SOURCE_DATE_EPOCH`.
- **Full `npm run bench`** (by hand, before a release; its JSON path is quoted in the release note): three families at 100, 500, 2000 (5000 timing-only), both qualities, `--view 2d` and `all`, median of 3 in-process runs, the node:test runner summary, one CLI wall time and the fresh-clone simulation (the tree copied without `vendor/three`, `node_modules`, `.dotfield`, `data`, `center`; the CLI spawned from `scripts/benchmark.mjs` only; commands counted until exit 0 for `--view 2d` and `--view all`). Everything the Markdown block leaves out — bytes, timings, the Node version, `engineDigests()` — lives in `.dotfield/benchmark/<stamp>.json`.
- **Not measured, and never claimed**: competitor renders (Phase 2 adapters for d2, mmdc and elkjs run only when installed, else `not run`), browser frame rates, visual quality and headset behaviour. Those come from receipts with `evidence.browser: captured` or stay `provisional`; a capture lives under the ignored `.dotfield/` and is never an input of the checklist block, so Dotfield's D6 (3D, VR) and D7 (4D viewer) cells print `present (provisional)` and `references/MATURITY.md` carries the capture state.

## 4. Reading the two parts together

The checklist names what each system has; the auto block says how well Dotfield's own version of it performs today, and the per-component rows of `references/V2_PLAN.md` §9 say which component flips which row. A row that prints `not_implemented` is the §0.1 opening condition for its v2.x ticket; a feature that reads `present` for a competitor and `absent` for Dotfield is a gap stated, not a gap scored.
