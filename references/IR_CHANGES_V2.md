# IR changes for v2 (binding for `ir-v2`; see V2_PLAN.md)

All additions to schemas/scene.schema.json are optional fields or enum/pattern extensions; `$id` stays `dotfield.scene/1`; every existing example and fixture validates unchanged; only the keyword subset lib/validate.mjs supports is used (type incl. type arrays, enum, const, required, properties, patternProperties, additionalProperties, items, min/maxItems, min/maxLength, maxProperties, pattern, minimum, maximum, oneOf, format date|date-time, $ref). Owner: component ir-v2 (sole writer of this file in v2.0). Items marked TICKET are not declared in v2.0.

1. `kind` enum: ["graph","room","timeline","board","workflow","meet"] → + "sequence", "lifecycle". Description: sequence = participants on lanes with ordered message edges; lifecycle = states with ordered transition edges.

2. `meta.theme` enum: unchanged in v2.0 (TICKET themes-presets adds "editorial", "blueprint" together with the CSS; until then a scene naming them fails DF_SCHEMA_ENUM, which is correct).

3. `edges[].kind` enum: + "message", "transition". `edges[].order` description becomes "Required on message and transition edges and on every edge of a sequence scene (DF_IR_ORDER_MISSING); equal order = one beat." New optional edge fields: `at` {$ref date} (the edge's own date; else derived), `from_side` and `to_side` {enum ["top","bottom","left","right"]} (port hints the channel router honours). `edges[].id` stays optional in the schema, but `DF_IR_EDGE_ID_REQUIRED` (topology, blocking) fires for every edge of a scene whose views.2d.layout is layered|sequence|lifecycle and for every message|transition edge: routes are keyed by id and a routed mode refuses an id-less edge (plan.skipped[]).

4. `nodes[]`: no new fields and no new kind in v2 (lifecycle states are any kind with tags "initial"/"final" and `shape: "pill"`; see open decision 1). `nodes[].pos` description adds sequence|lifecycle to the kinds that read it.

5. Scene-level geometry tables beside `positions` (both pattern-keyed open maps, so openPaths(scene) becomes exactly ["$.ext","$.labels","$.nodes[*].fields","$.positions","$.routes"]; test/ir-gates.test.js and references/IR.md §6 updated by ir-v2):
   - `routes`: { "type": "object", "patternProperties": { "^[a-z0-9][a-z0-9_.:-]{0,79}$": { "type": "array", "minItems": 2, "maxItems": 64, "items": {$ref vec2} } }, "additionalProperties": false, "description": "Edge id -> polyline in viewBox px. Dense in routed modes (layered, sequence, lifecycle: every edge with an id, the chord included); sparse elsewhere (only edges lib/layout/route.mjs changed). svg, the layout gate and three.mjs read scene.routes[id] ?? routePoints()." }
   - `labels`: { "type": "object", "patternProperties": { "^[a-z0-9][a-z0-9_.:-]{0,79}$": { "enum": ["below","above","right","left","center"] } }, "additionalProperties": false, "description": "Node id -> label side, written by lib/layout/labels.mjs only where it differs from the shapes.json default; absence means the default side." }
   - `laid_out` description: "true once positions holds every node and routes is complete for the mode (routesComplete: dense in routed modes); goldens never re-simulate (DF_LAYOUT_ROUTE_MISSING when a routed mode lacks an entry or a key names no edge)."

6. `views.2d`: `layout` enum + "layered", "sequence", "lifecycle"; new `direction` {enum ["down","right","up","left"]} (layered and lifecycle only; default down for workflow, right for lifecycle); new `label_budget` {type integer, minimum 0, maximum 2000} (labels beyond the top-N by weight are hover-only and unmeasured; default all up to 300 nodes, then 300); new closed `plan` { "type":"object", "additionalProperties": false, "required": ["mode"], "properties": { "mode": {enum ["force","cluster-disc","grid","timeline","lanes","metric","layered","sequence","lifecycle"]}, "reversed": {$ref id_list}, "skipped": {$ref id_list}, "layers": {type integer, minimum 0}, "dummies": {type integer, minimum 0}, "crossings": {type integer, minimum 0}, "beats": {type integer, minimum 0}, "viewbox_grown_from": {$ref vec2} }, "description": "Written by lib/layout for every mode; read, never recomputed, by the layout gate (DF_LAYOUT_LAYER_CYCLE_BROKEN from reversed, DF_LAYOUT_VIEWBOX_GROWN from viewbox_grown_from) and by svg-chrome.mjs. Arrays, so no new open path." }.

7. `views.vr`: new `snap_turn_deg` {enum [0,30,45,90]} (default 45; 0 disables) — declared in v2.0 so a scene may author it; honoured by TICKET three-4d.

8. `views.time` (new property of `views`, closed object):
   { "type": "object", "additionalProperties": false, "required": ["axis"], "properties": {
     "axis": {enum ["date","order"]},
     "field": {enum ["happened_on","captured_on","remembered_on","released_on"]},
     "from": {oneOf [{type string, format date}, {type integer, minimum 0}, {type null}]},
     "to":   {oneOf [{type string, format date}, {type integer, minimum 0}, {type null}]},
     "step": {enum ["day","week","month","year","event","beat"]},
     "playhead": {oneOf [{type string, format date}, {type integer, minimum 0}, {type null}]},
     "cumulative": {type boolean},
     "motion": {enum ["still","trace","playback"]},
     "trace": { "type":"object","additionalProperties":false,"properties": { "trail": {type number, minimum 0.05, maximum 1}, "beads": {type integer, minimum 1, maximum 8}, "duration_ms": {type integer, minimum 400, maximum 20000} } } } }
   (oneOf instead of a type array so format applies to strings and minimum to integers unambiguously; test/validate.test.js pins `from: 12` passes, `from: '2026-13-40'` fails DF_SCHEMA_FORMAT, `from: -1` fails DF_SCHEMA_MINIMUM.) Gate rules (lib/gates/topology-views.mjs, blocking unless noted): DF_IR_TIME_WINDOW_INVALID when from > to, playhead outside [from, to], a date value on an order axis or an integer on a date axis, or step "beat" on a date axis / a date step on an order axis; DF_IR_TIME_RANGE_EMPTY (non-blocking) when axis is date and no node carries the field (or captured_on).

9. `views.interactive.steps` (new): { "type":"array","maxItems":64,"items": { "type":"object","additionalProperties":false,"required":["id","nodes"],"properties": { "id": {$ref id}, "label": {$ref short_text}, "caption": {type string, maxLength 200}, "nodes": {$ref id_list}, "edges": {$ref id_list}, "playhead": {oneOf [{type string, format date}, {type integer, minimum 0}, {type null}]} } } }. `presentation[]` stays (one-node-per-step shorthand; steps[] supersedes when present). Gate: DF_IR_DANGLING_VIEW_REF for any steps[].nodes/edges id, views.interactive.focus, presentation[] entry or views.vr.entry_node that resolves to nothing (replaces the DF_IR_DANGLING_EDGE reuse at topology.mjs:161-163; DF_IR_DANGLING_EDGE is again edges-only). This is a behaviour change on existing scenes: ir-v2 greps test/, references/ and examples/ for DANGLING_EDGE on view paths before landing, renames any such fixture in the same commit, and records the change in references/IR.md §10.

10. `delta`: TICKET compare. Not declared in v2.0 (no scene may carry a delta block before the verb that writes it exists). When the ticket opens: a closed scene-level object with before/after {ref, digest}, pairs, unpaired_ratio, nodes[] {id, change enum [added,removed,changed,moved,same], axes[] enum [semantic,topology,geometry,provenance,presentation,evidence,scope], from vec2, label}, edges[] {id, change, axes}, counts, claims const "no risk assessment"; plus schemas/delta.schema.json (`dotfield.delta/1`) and a new rule family `delta` (PINNED.rule_families 24).

11. Topology constants (lib/gates/topology.mjs): SCENE_KINDS + sequence, lifecycle; EDGE_KINDS + message, transition; DF_IR_SELF_EDGE skipped when scene.kind is sequence or lifecycle (message/transition self loops are drawn by the layouts); DF_IR_ORDER_MISSING when an edge of kind message|transition, or any edge in a kind sequence scene, lacks an integer order; DF_IR_EDGE_ID_REQUIRED as in item 3; DF_IR_LIFECYCLE_NO_INITIAL (non-blocking) when a lifecycle scene has no node tagged "initial". View-reference and time-window checks move to lib/gates/topology-views.mjs (≤ 140 lines) so topology.mjs stays well under 400.
