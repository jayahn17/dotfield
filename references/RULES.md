# Rule catalog — `DF_*` codes (generated)

> Generated by `node scripts/gen-rules-md.mjs` from `lib/rules/*.mjs` (catalog version 1). Do not edit by hand: `node scripts/gen-rules-md.mjs --check` fails when this file is stale and `npm run rules:md` regenerates it.

Every gate, command, route and tool reports the same check shape, `{code, gate, blocking, status, path?, message?, repair?}`, built by `finding()` in `lib/rules.mjs`. A failing check carries the repair sentence below; the skill applies it by code and never edits `lib/`, `schemas/` or `renderers/` to make a gate pass. A code lives in exactly one family file, `lib/rules/<family>.mjs`; a later component adds a code only to its own family. `Exit` is the process exit a *blocking* failure maps to (`lib/exit-codes.mjs fromReceipt()`); the default is 2.

## Exit codes (`lib/exit-codes.mjs`)

| Code | Name | When |
|---|---|---|
| 0 | `ok` | the command finished what it was asked to do |
| 1 | `unexpected` | an unexpected error; a receipt with status error is still written |
| 2 | `gate` | a blocking gate failed; the receipt lists every check that ran |
| 3 | `awaiting_owner` | stopped at the approval hop, an owner gate, or a not-owner refusal |
| 4 | `storage` | a typed storage fault (503); nothing was partially written |
| 5 | `provider` | the provider adapter is unavailable or answered badly |

## Gate order

| Verb | Order |
|---|---|
| `render` | schema → topology (incl. fields budget) → privacy (HMAC stamp, viewer exclusion, foreign bodies, absolute paths, taint) → layout → render → receipt; the first blocking failure stops with exit 2 |
| `validate` | schema → topology → privacy → layout (no render output); room manifests add the room family |
| `share project` | schema → share → receipt |
| `run` | DF_RUN_ROUTE_PARITY, DF_RUN_NO_CHALLENGER, DF_RUN_BUDGET_EXCEEDED, DF_RUN_WRITE_BEFORE_APPROVAL, DF_RUN_FOREIGN_UNFENCED → receipt |
| `verify` | the receipt family over one receipt.json |
| `compare` | load both (an unreadable input is DF_DELTA_INPUT_BLOCKED) → DF_DELTA_KIND_MISMATCH → each input: schema → topology → privacy → layout (DF_DELTA_INPUT_BLOCKED; DF_DELTA_LAID_OUT_COLD, non-blocking, when one is laid out cold) → diff (DF_DELTA_NO_STABLE_IDS, DF_DELTA_EDGE_PAIRED_BY_ENDPOINTS) → the after scene with its delta: schema → topology → privacy → layout, and delta.json against schemas/delta.schema.json → render → receipt |
