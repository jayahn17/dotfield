## 0. Thesis

One positions table, one set of geometry tables beside it, one playhead, one standalone HTML. A stranger writes ten lines of JSON (`dotfield.sketch/1`), runs one command with no output path, and gets a gated 2D/3D/VR page written inside `.dotfield/renders/` whose receipt reads `0 fail` — with no privacy gate loosened to get there. The layout optimises for what the gate measures (label boxes, route polylines) instead of detecting it afterwards, and writes `routes` and `labels` beside `positions`, read by `svg.mjs`, `lib/gates/layout.mjs` and (later) `three.mjs` through one accessor, so what is drawn is what was measured. Time is one explicit, serialised playhead (`views.time`): computed in Node by `lib/time/playhead.mjs`, mirrored by `renderers/viewer/time.js` under a deep-equality test, and applied as a pure function so the still frame at any `t` carries the whole meaning; motion is opt-in, finite and seekable. `scripts/benchmark.mjs` is the contract: every claim in this plan is a number or a boolean it computes; its Markdown block holds only what cannot churn (input digests, counts, booleans), its JSON holds everything else, and nothing claims visual or headset quality without a captured screenshot.

## 2. Type coverage model

Types are not renderers. Every architecture type is a combination of three ideas the IR already half-has: **lanes** (groups of kind `lane`, and sequence rows by `edge.order`), **layers** (Sugiyama ranks in 2D, lift tiers or the tier wall in 3D) and **states** (nodes born by an ordered edge). Each type below is a sketch template (`templates/<type>.sketch.json`, ≤ 10 lines), a scene kind + layout, a 3D mode, and the gates that apply.

| Type | `kind` | `views.2d.layout` | 3D | v2.0 | Notes |
|---|---|---|---|---|---|
| architecture / C4 containers | `workflow` | `layered` (`down`) | `lift` | template + layout | zones = groups kind `zone` drawn as axis-aligned bands; channel routes; ports from `from_side`/`to_side` |
| workflow (archify row/col) | `workflow` | `grid` | `lift` | unchanged | archify imports keep their hand grid; `routePlanGrid` writes orthogonal channel routes for back edges |
| dataflow | `workflow` | `layered` (`right`) | `lift` | template + layout | `flow` edges with `order`; `views.time {axis: order}` opt-in |
| sequence | `sequence` (new) | `sequence` (new) | `lift` flat | template + layout | participants = nodes; messages = `message` edges with required `order` and `id`; lifelines derived from the committed tables; self edges allowed |
| lifecycle / state machine | `lifecycle` (new) | `lifecycle` (new) | `lift` | template + layout | states = nodes (default kind `event`, `shape: pill`) tagged `initial`/`final`; transitions = `transition` edges with required `order` and `id`; self edges allowed |
| graph / knowledge web | `graph` | `force` or `cluster-disc` | `lift` | repair passes | label-aware passes, route-around, parallel-edge fan |
| timeline / Gantt-lite | `timeline` | `timeline` | `tier-wall` | time block | `views.time {axis: date}` gives the ruler |
| board | `board` | `lanes` | `lift` | unchanged | |
| room | `room` | `metric` | `metric` | unchanged | |
| meet | `meet` | `cluster-disc`/`lanes` | `lift` | unchanged | |
| org tree / mind map | `workflow` | `layered` over a tree | `lift` | template | no new code: layered with one source |

Importing archify `sequence|lifecycle` files is the `importers-parity` ticket (§11); in v2.0 those types are **authored** (templates) and the benchmark row reads `archify.types_supported: 3 (architecture, workflow, dataflow); refused_by_name: sequence, lifecycle; archify_total_types: unknown until the corpus ticket pins a commit`. (Both tickets landed 2026-10-08: the row now reads `types_supported: 5 of 5`, `refused_by_name: none`, `archify_total_types: 5`, `corpus_showcase_clean: 15/15`.) ## 3. Layout algorithms (all pure, seeded, `+ - * / sqrt` only, index-ordered sums so `verifyDeterminism()` keeps passing on Node 22/24)

**Geometry tables and the mode contract** (absorbs: sparse-routes fatal, id-less-edge fatal, plan fatal, viewBox constraint, determinism constraint).

- A mode returns either today's `[[x, y], …]` or `{points, routes?, sides?, plan?, viewBox?}`; `lib/layout/index.mjs run2d` normalises both.
- **Routed modes** (`layered`, `sequence`, `lifecycle`) write `routes` **dense**: every edge that has an id gets an entry, the chord included; an edge without an id is refused by the mode (`plan.skipped[]`) and by the topology gate (`DF_IR_EDGE_ID_REQUIRED`, blocking, for every edge of a scene whose `views.2d.layout` is a routed mode and for every `message|transition` edge). Sketch expansion and the room projector always mint ids (`e<index>` / `e-<n>`), so no shipped path produces an id-less edge (today: 0 of 56).
- **Free-form modes** (`force`, `cluster-disc`) and the lattice modes (`grid`, `timeline`, `lanes`) write `routes` **sparse**: only the edges `route.mjs` changed (route-around via points, parallel fan, grid channel). `DF_LAYOUT_ROUTE_MISSING` is never emitted for them; a committed free-form scene without routes simply draws chords, as today.
- `routesComplete(scene, mode)` beside `positionsComplete()`: routed mode → every id'd edge has an entry and every key names an edge; otherwise → every key names an edge. `laid_out: true` means positions and routes are complete for the mode. A `laid_out` scene that fails `routesComplete` is **not** re-run (goldens never re-simulate): the gate emits `DF_LAYOUT_ROUTE_MISSING` (blocking) with the repair "remove `laid_out` so layout runs again, give the edge an id, or delete the key that names no edge". A missing position is the same (`DF_LAYOUT_POSITION_MISSING`): `layoutScene` returns every `laid_out` scene as committed, complete or not, so `validate` and `render` exit 2 on it instead of quietly re-laying it (`test/layout-truth.test.js` runs both through the CLI).
- `labels` stays sparse everywhere: the default side is a pure function of `renderers/shapes.json`, so `labelSide(scene, node, shapes) = scene.labels?.[id] ?? shapes default` is decidable without re-simulation and the gate measures exactly what is drawn; there is no `LABEL_MISSING` code.
- `views.2d.plan` is a **closed object written by every mode** `{mode, reversed?: id_list, layers?: int, dummies?: int, crossings?: int, beats?: int, viewbox_grown_from?: vec2}`; the gate reads it (never recomputes it): `DF_LAYOUT_LAYER_CYCLE_BROKEN` from `plan.reversed`, `DF_LAYOUT_VIEWBOX_GROWN` from `plan.viewbox_grown_from`. No new open path (`reversed` is an array). `test/layout.test.js` asserts `layoutDetailed(scene, {force: true}).plan` deep-equals the committed `views.2d.plan` of every shipped scene (cold-run reproducibility, not gate-vs-layout agreement).
- **viewBox**: `prepare()` fixes the frame from `views.2d.viewBox` (authored, else `defaultViewBox(n, spacing, meanLabelW)`); a mode may return `viewBox` (sequence derives height from beats; free-form repair returns the union of the frame and the label-box bounding box plus padding when labels overflow); `layoutScene` writes `views.2d.viewBox = union(authored ?? default, returned)` — grow, never shrink — and, when it grew an **authored** box, writes `plan.viewbox_grown_from = [w, h]`. The browser never recomputes a frame for a laid-out scene because every laid-out scene carries a written viewBox (pinned by `test/examples.test.js`); `three.mjs frameOf`'s default branch becomes dead code and is deleted in the `three-4d` ticket.
- **Determinism** is proven over every table: `verifyDeterminism(scene, ctx, runner = layoutTables)` canonicalises `{positions, routes, labels, plan}` from two cold forced runs; a diff names the table and key in `DF_LAYOUT_NONDETERMINISTIC`. **Committed tables are cold-run outputs**, with one named exemption: `examples/scene-graph.json`, the VISION §4 example, keeps its authored positions (pinned exactly by `test/ir-gates.test.js`, so any edit is visible) beside the plan a cold run writes. Every other example, every pack scene and every draft pack scene equals a cold run table for table (`test/layout-truth.test.js`; `scripts/relayout-scenes.mjs packs packs/draft --check`). `ctx.incremental` (warm start from an existing table) is used only by the benchmark's one-edit-stability row, never by `render`, `validate` or `scripts/relayout-scenes.mjs --check` (which runs cold).
- Accessors: `edgePolyline(scene, edge, from, to) = scene.routes?.[edge.id] ?? routePoints(edge, from, to)` and `labelSide(scene, node, shapes)`; `svg-edges.mjs`, `lib/gates/layout.mjs` and the `three-4d` ticket read nothing else.
