While Dotfield is nested inside son, the dot-files above are inert (Claude Code and `preview_start` read them from the project root); `AGENTS.md` says the MCP server and the preview are exercised as `node dotfield/mcp/stdio.mjs` and `node dotfield/server/serve.mjs` from the son root until the split. That works because `lib/context.mjs findRoot()` resolves the center in this order: `DOTFIELD_ROOT` when set, the nearest ancestor of cwd holding `center/center.config.json`, then the engine's own folder when cwd is one of its ancestors (the nested case, center or not, so `init` from the parent writes the engine's `center/` and never one beside it), else cwd (a project using the engine through npx); `test/cli-core.test.js` holds the order.

## 9. Customization surface

**A customer edits (all under `center/`, all schema-validated, all migratable):**
- `center.config.json` — `{schema_version, center{name, tagline, owner_person_id, locale}, installed_packs[{id, version, digest}], provider{adapter, model, max_tokens_per_run, allow_nested: false}, server{port, host}, privacy{default_privacy_level: "private"}, connect{threshold}, approval{max_records_per_proposal: 200}, store{allow_env_pins: false, object_store_url: null}, conductor{display, lens}}`
- `brand.json` — `{name, accent, surface, ink, font{display, text, mono} (enum of local stacks), room_preset, files[]?, logo?, radius?, density?}`
- `rooms/<id>/`, `people/`, `docs/{README.md, AGENTS.md, recipes/}` (the customer's prose), `ext: {}` on any manifest or scene; `importers/*.mjs` is reserved for sandboxed customer importers (planned, §13 — no verb reads it in 0.1.0).

**A customer never edits:** `bin/`, `lib/`, `schemas/`, `renderers/`, `server/`, `mcp/`, shipped `importers/`, `migrations/`, `vendor/`, `packs/`, `test/`, the three root manifests. `engine.manifest.json` hashes them (minus `fork_editable[]`); `doctor` reports `DF_ENGINE_MODIFIED`; receipts print `match_release: false` (meaning: an unintended local edit, not tamper evidence).

**Extension points, each a pure function with a schema on both sides and a test:** `views.json` operators; provider adapters; one object-store adapter whose target is declared in `center.config.json.store.object_store_url` (env pins `DOTFIELD_STORE_<ROOM>_FILE` are honoured only under `NODE_TEST_CONTEXT` or `store.allow_env_pins: true`, and every receipt prints `store.target`); `x-<kind>` node kinds with a `shapes.json` row; layout modes under `lib/layout/`; lenses; local packs. The MCP tool list is fixed. **Planned, not wired:** sandboxed `actions.mjs` and `center/importers/*.mjs` — `lib/sandbox.mjs runModule()` exists and is tested, but no CLI verb, route or MCP tool calls it yet; `import records` picks an importer by extension or folder shape among the six shipped ones only. They move out of `planned` in §13 when a verb runs them, each with a test and a `DF_SANDBOX_*` fixture.

**The under-an-hour path** (README states the measured time with date and tester role, or "not yet timed"): clone, `npm install` · `init --pack robotics-lab --name "Hall Lab"` · `doctor` green, `serve`, open the seeded rooms · `import records experiments packs/robotics-lab/examples/runs.csv` → proposal → review the summary → approve on `/inbox` · open `claude`, "plan a review of last week's runs"; Claude runs `plan`/`run`, stops at `awaiting_owner` · `connect --between experiments,papers` · `render room:experiments/graph out.html --view all --for ada` and send that one embedded HTML. No source file opened.

**Upgrade path:** a fork's commits touch only `center/` and the `fork_editable[]` root files (`data/` and `.dotfield/` are ignored); the template ships no `center/`, so `git pull upstream main` needs no merge driver; then `migrate --dry-run`, `migrate` (pack files the owner never touched move to the shipped version, owner edits stay, the shipped copy waits under `.dotfield/migrate-<ts>/shipped/`, `migrate --resolved` once merged), `validate all`, `npm test`, and commit `center/`. `test/fork-sim.test.js` runs `init --pack robotics-lab` in a fork, customises and commits the center, merges an upstream commit touching `lib/`, `schemas/` and two pack files, and asserts no conflict, no `DF_ENGINE_MODIFIED`, the untouched file updated and the edited one kept.
